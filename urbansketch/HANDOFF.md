# Передача контекста: UrbanSketch MVP

Документ для продолжения работы в новой сессии. Прочитайте его целиком перед
первым изменением кода — здесь зафиксированы принятые решения и то, что уже
проверено, чтобы не переделывать заново.

## 1. Что это

Инструмент предпроектной оценки земельного участка для девелопера:
контур участка → пятно застройки → посадка корпусов → ТЭП, баланс территории,
проверка норм и инсоляции → экспорт.

Ориентир — сервис **urbansketch.pro** (генеративное проектирование, тарифы
190/490/890 тыс ₽ в год, шесть модулей: границы участка, генерация застройки,
баланс территории, инсоляция, инженерные сети, квартирография). Задача была
поставлена как «сделать такой же сервис»; выбранная стратегия — не копировать
все шесть модулей поверхностно, а довести до безупречного счёта ядро
(ТЭП + нормы + инсоляция) и на нём заходить к первым клиентам.

## 2. Где код и как запустить

- Репозиторий: `Rostik43/artel-club`, ветка **`claude/urban-sketch-service-9vm5t4`**
- Приложение целиком лежит в папке **`urbansketch/`** и не зависит от остального
  репозитория: папку можно вынести в отдельный репозиторий как есть.
  Пользователь планировал именно отдельный репозиторий, но создать его из
  сессии было нельзя (доступ ограничен `artel-club`) — **вопрос открыт**.

```bash
cd urbansketch
npm install
npm run dev      # разработка
npm run build    # сборка
npm run smoke    # прогон расчётного ядра в Node, без браузера
```

Живая демо-сборка (один самодостаточный HTML, публикуется из папки `dist`):
https://claude.ai/code/artifact/bc4f0ab7-7638-4f6e-8196-89e491ab816c
Чтобы обновить её после изменений — пересобрать, заинлайнить CSS и JS в один
файл и опубликовать по **тому же URL** (иначе создастся второй артефакт).

Эти числа подтверждены прогоном, на них удобно ловить регрессии:

| Проверка | Ожидаемое значение |
|---|---|
| `samples/test-parcel-200x150.dxf` | площадь 30 000 м², 4 вершины |
| Пятно застройки при отступе 3 м | 27 936 м² |
| `samples/parcel-rosreestr.xml` | 25 603 м², номер 66:41:0704001:1234 |
| `samples/parcel.geojson` | 51 555 м² |
| Плотность на участке 3 га | 44 790 м² квартир ÷ 3 га = 14 930 м²/га |
| Солнце 22 марта, 12:00, широта 55,75° | высота 34°, тень строго на север |

`npm run smoke` гоняет четыре контура и падает, если хоть в одном варианте
нарушены разрывы, пятно, плотность или процент застройки. После любой правки
генератора или геометрии — запускать обязательно.

## 5. Принятые решения

- **Локальная метрическая система**: x — восток, y — север, метры. Кадастровый
  XML отдаёт X как север, поэтому при импорте оси меняются местами.
- **Каждый кандидат в генераторе проверяется до постановки**, а не после.
  Поэтому выданный вариант уже проходит `runChecks` — это инвариант, его
  проверяет smoke-тест.
- **Нормативы — редактируемые пресеты, а не выписка из МНГП.** Так и подписано
  в интерфейсе. Оцифровка настоящих МНГП по регионам — отдельная работа
  нормоконтролёра, не программиста, и это главный недооценённый объём в проекте.
- **Инсоляция намеренно упрощена** и подписана как инструмент отбраковки
  вариантов, а не расчёт по СанПиН. Врать про соответствие нормам нельзя.
- **Один экран без роутинга**: слева ввод, по центру план, справа показатели.
  Пересчёт всего на каждое изменение — на текущих объёмах это ~100 мс.
- Комментарии в коде и весь интерфейс — на русском.

## 6. Ограничения текущей версии

- Инсоляция: 22 марта, окна на 1,5 м, затенение только корпусами внутри участка,
  без окружающей застройки, рельефа и разной высоты этажей.
- Отступ от границ — общий плюс отдельный для красных линий; индивидуальный
  отступ по каждой стороне не редактируется.
- Нет квартирографии, инженерных нагрузок, дорожной сети, 3D, карты-подложки,
  бэкенда и аккаунтов.
- Экспорт в DXF отсутствует (есть SVG и GeoJSON).
- Генератор упирается в норматив плотности, но дворы и проезды не проектирует —
  свободная территория считается остатком, а не планируется.

## 7. Очередь задач

По убыванию отношения пользы к трудозатратам:

1. **Карта-подложка (OSM) и рисование контура на карте.** Есть у конкурента,
   делается за день, сильно влияет на первое впечатление.
2. **Экспорт в DXF.** Проектировщик должен получить файл, который откроется
   в AutoCAD, а не только картинку.
3. **Индивидуальные отступы по сторонам участка** — сейчас частая причина
   расхождения с реальным ГПЗУ.
4. **Улучшение генератора**: проектирование проездов и дворов, а не остаток;
   ориентация корпусов по инсоляции; больше стратегий.
5. **Квартирография**: разбивка секции на типы квартир по заданной матрице,
   с выдачей структуры продаж.
6. **Инженерные нагрузки**: водоснабжение, электричество, отопление по
   удельным показателям на жителя — механический расчёт, быстро.
7. **Инсоляция ближе к СанПиН**: окружающая застройка за границами участка,
   расчётные точки на разных этажах, три расчётных дня.
8. **Оцифровка МНГП по регионам** — долго, но именно за это платят.
9. **Бэкенд и аккаунты**: хранение проектов, совместная работа. Только когда
   ядро перестанет меняться каждый день.

## 9. Как работать дальше

- Все изменения — в ветку `claude/urban-sketch-service-9vm5t4`.
- После правок расчётов: `npm run smoke`, затем прогон в браузере
  (импорт → генерация → экспорт), и только потом коммит.
- Не занижать оценки и не выдавать упрощённые расчёты за нормативные:
  в этом продукте цена ошибки — инвестиционное решение застройщика.
